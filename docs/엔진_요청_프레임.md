# HBEngine 요청: 프레임 목표 (PC 120fps, 모바일 60fps)

Auric Loop 쪽에서 할 수 있는 최적화는 끝났습니다(탄·적·이펙트 화면 밖 대기, 값이 바뀔 때만 엔진 호출). 남은 시간은 엔진의 프레임마다 드는 고정 비용입니다. 이 문서의 한 가지만 부탁합니다.

## 지금 측정 (2026-10-06, 설치본 `42bcd763ffa422e3`, 편집기 실행, 프로파일러 `profiler.read`)

장면: `Assets/Scenes/Test_Valen.hbscene.json` (오브젝트 424개, 대부분 화면 밖 대기 풀)

| 상황 | 게임 프레임 중앙값 | 상위 5% | 렌더 |
|---|---|---|---|
| 가만히 서 있음 | 12.0ms | – | 1.3ms |
| 전투 (해골 5, 웨이브 등장·피격·탄) | 12.5ms | 15.3ms | 1.3ms |

가만히 서 있는 한 프레임의 내역:

| 구간 | 시간 |
|---|---|
| C++ 프레임·타이머 왕복 2번 (모듈마다 1번씩?) | 1.5ms + 1.8ms |
| C++ 호출 1번 (`TopDownShooter.Update`) | 5.5ms. 그중 사용자 C++ 실행(`invokeMs`)은 0.67ms. 나머지는 patch 1.4, worker 2.8, serialize 0.7, sync 0.3, validate 0.3 |
| 물리·AI·애니메이션 | 2.3ms |
| 합계 | 약 11~12ms (최대 약 85fps) |

- 2.6초 동안 게임 프레임 150개가 돌았습니다(약 58fps). 편집기 창이 60Hz 가상 디스플레이(Parsec)에 있어서 60에 묶였는지, 엔진이 60으로 고정하는지 구분하지 못했습니다. 실제 모니터는 RTX 4070 SUPER의 164Hz입니다.
- 모바일 60fps는 실기기가 없어 측정하지 못했습니다.

## 바라는 것

1. **게임 루프를 디스플레이 주사율(120·144·164Hz)까지 돌리기.** 물리는 고정 1/60초 그대로 두고 보간해도 됩니다. Game.exe와 편집기에서 60에 묶이지 않는지 확인 부탁합니다.
2. **프레임마다 드는 엔진 고정 비용을 4ms 이하로.** PC 120fps(8.3ms)에서 게임 규칙·물리·렌더를 뺀 몫입니다.
   - 프레임·타이머 왕복 2번과 `Update` 호출을 한 번의 왕복으로 묶기
   - 바뀐 오브젝트만 patch·serialize하기. 화면 밖에 세워 둔 풀 오브젝트(정적·움직이지 않음)는 건너뛰기
   - 움직이지 않는 정적 충돌체와 잠든 물리 몸체를 물리 단계에서 빼기
3. **Android 중급 기기에서 같은 장면 60fps.** 실기기 측정은 휴대폰을 연결하면 주인님이 도와줄 수 있습니다.

재현: `tools/preview.ps1 -Scene Test_Valen`으로 편집기를 열고 `profiler.record` → F9(첫 전투방) → 터치 공격 유지 6초 → `profiler.read`.
