# 엔진 요청: 네이티브 실행기에서 SpriteRenderer drawMode "tiled"가 늘어나 그려짐 (2026-10-31)

엔진 7a1a8f8 Windows 네이티브 패키지(perf 프로필, Test_Boss)에서 던전 바닥·벽(`Floor#`, `Cap#`, `Face#`, `LowWall#` 등)이 반복 타일 대신
32px 그림 한 장이 방 크기로 늘어나 **회색 판**으로 보인다. 같은 엔진·같은 장면의 WebView2 패키지(`AURIC_RUNTIME=webview`)는 정상.

- 컴포넌트: `SpriteRenderer` `drawMode: "tiled"`, `texture: Assets/Tiles/T_DungeonFloor.png`, `pixelsPerUnit: 32`, `useCustomSize: true`, 크기(width·height)는 C++가 방마다 바꿈
- 거점(타일맵)은 네이티브에서도 정상

요청: 네이티브 SceneRenderBridge가 tiled 모드(텍스처 반복, UV = 크기 × pixelsPerUnit / 텍스처 크기)를 지원.
그 전까지 Auric Loop PC 패키지는 WebView2 실행기로 배포한다 (`tools/package.mjs`, `AURIC_RUNTIME=webview`).

## 추가 (a471833, 2026-10-31)

반복 타일은 고쳐졌다(던전 바닥·벽 정상). 다만 같은 게임·같은 보스방(perf, --hidden 1800프레임)에서 프레임 계산 시간이 나빠짐:
- 7a1a8f8: 보통 3.3ms, 상위 5% 32ms, 20ms 넘는 프레임 148개
- a471833: 보통 7.3ms, 상위 5% 75ms, 526개 → 게임에서 매 프레임 `Sprites::SetSize`(예고 범위 차오름)를 배율로 바꾼 뒤 4.9ms / 66ms / 419개
크기·컴포넌트 값을 바꿀 때마다 메시를 다시 만들고 표시 갱신을 기다리는 비용으로 보임. 바뀐 값이 같거나 위치·배율만 바뀌면 건너뛰거나, 기다리지 않고 다음 프레임에 반영해 주길 요청.
