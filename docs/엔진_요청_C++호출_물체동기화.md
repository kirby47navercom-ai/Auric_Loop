# 엔진 요청: C++ 호출마다 장면 물체 전체를 직렬화하는 비용 (2026-10-31)

저사양 PC(Intel UHD 620·램 8GB)에서 돌아야 하는데, 남은 CPU 비용 대부분이 엔진 쪽 동기화라 게임 쪽에서 줄일 수 있는 폭이 작다.

## 측정 (엔진 467f512, `tools/run-project.mjs` 헤드리스 + `--cpu-prof`, Test_Boss 1500프레임)

- 게임 C++ 호출은 프레임당 1번(`TopDownShooter.Update`)뿐. 적 FSM 호출은 상태가 바뀔 때만.
- 그런데 그 1번마다 `nativeRequestWorld` → `nativeWorld(objects)`가 위젯·컴포넌트를 뺀 **장면 물체 전체(던전 약 495개)**를 넘기고,
  `native-transport.js`의 `nativeRowJSON`이 매번 전부 `JSON.stringify`해서 이전 행과 비교한다.
  - 평소 프레임: 바쁜 시간의 약 25%가 이 직렬화(`nativeRowJSON` 16%, transport 익명 함수들)
  - 물리 `physics-world.js` `sync`·`advance`: 약 20% (정적 충돌체 포함 186개)
- 보스전에서 30~50ms로 튀는 프레임: C++ 호출 왕복 7ms → 17ms, 나머지(물리·BP) 5ms → 18ms. 활성 물체 수는 그대로(약 94개)라 물체가 늘어서가 아님.
- 네이티브 패키지(--hidden --report) 보스방: 프레임 계산 보통 4.6ms, 상위 5% 38ms. 약 2초마다 10프레임 정도 30ms대가 이어짐.

## 요청

1. C++ 호출 요청에 바뀐 물체만(더티 행) 보내거나, C++가 읽는 물체로 범위를 좁히기. 위치·스프라이트만 바뀐 행은 필드 패치로.
2. 화면 밖에 세워 둔(풀) 물체·정적 장식은 동기화·물리 sync 대상에서 빼는 표시(예: 컴포넌트 `nativeSync:false`, 정적 바디 sleep).
3. 보스전의 주기적 10프레임 튐을 엔진 프로파일러(C++ 구간 시간 포함)로 볼 수 있게: 지금은 헤드리스에서 C++ 구간을 나눠 볼 방법이 없음.

게임 쪽에서 이미 한 것: 60프레임 고정, 블룸 끔, 물리 한 프레임 최대 2단계, 거점 장식 애니메이션 멈춤, 숲 바깥 충돌 제거 (`tools/light_scene.mjs`).
